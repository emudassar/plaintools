# Content rules

Read this before writing any page copy. These are not style preferences — breaking them costs
the site.

## The decision rule

Before writing a page, answer all six. If you cannot, the page should not exist yet.

1. Who is this page for?
2. What specific problem does it solve?
3. What should the visitor understand or be able to do afterwards?
4. Why is this more useful than what already ranks?
5. What original information, functionality, evidence or explanation does it add?
6. What limitations or uncertainties must be disclosed?

Then: **would this page genuinely help its intended audience if Google Search did not exist?**
If honestly no, improve it or do not ship it.

## What the site's original contribution actually is

**It is:** working functionality, built carefully over a source that can be cited. A visitor gets
in one step what would otherwise take a portal session, a PDF, a spreadsheet, or arithmetic they
would rather not do.

**It is not:** expertise, first-hand testing, original research, or field experience. The site
has none of those and must never imply them.

Write as a **competent, careful interface to information that already exists** — not as an
authority on soil science, or paint, or whatever the next tool is about. Get that right and the
E-E-A-T story is honest and defensible.

## Never fabricate — zero tolerance

Data sources, endpoints, formulas, datasets, statistics, study findings, citations, source URLs,
test results, worked examples with unverified numbers, API responses, personal experience, field
testing, photographs, surveys, case studies, credentials, licences, endorsements, awards, search
volumes, traffic estimates, difficulty scores, revenue projections.

If a number appears on a page, you must be able to say where it came from. **If you did not run
it, do not say you ran it.**

## Structure — the tool comes first

H1, one-sentence tagline, then the **working tool**. No preamble above it. Supporting content
sits below and exists to help the visitor use the tool and read the result.

Use only the sections that materially help *this* tool. Do not stamp every section onto every
page, and do not repeat the same generic explanation across pages. That is what makes a
calculator farm look like one.

## The `uses` section — 10 items

Each is **a specific person with a specific problem and a real consequence**, not a category.

- Bad: "Real estate" / "Gardening" / "Construction"
- Good: "Checking foundation risk before buying a house"
- Good: "Estimating whether a rural lot can take a septic system"

Name what actually goes wrong — a cracked slab, a refused septic permit, a season lost to the
wrong amendment. That is what the searcher typed their query about.

Ten genuinely distinct uses, or fewer good ones. **Never inflate to hit a word count.**

`uses.heading` is written out, not derived. "10 practical uses for What Soil Type Is My Property"
is not English.

## The `dataSection` — where trust is won

Three to five paragraphs plus 3–4 real source links. Must cover:

1. **What the source or method actually is** — who produced it, how, over what period. For a
   calculation, state the formula and where it is documented.
2. **How this page gets its answer** — a live query, a bundled dataset, or maths in the browser.
   Say whether anything is stored or sent anywhere.
3. **What its limits are** — resolution, rounding, assumptions, and the inputs where it stops
   being reliable.
4. **What it must not be used for** — where a professional test, measurement or opinion is
   required and no published figure substitutes for it.

Paragraphs 3 and 4 earn the trust. A page that volunteers its own limitations reads as credible;
one that hides them reads as a content farm.

**Link the official tool where one exists.** Sending a user there when they need the full record
is a trust signal, not lost traffic.

## FAQs — 6 to 8

Real questions a user of *this* tool would ask:

- "Is this the same data as \[the official tool]?"
- "Why did it give me no answer for my input?"
- "How accurate is this for my specific case?"
- "Can I use this instead of \[the professional test]?" (usually no — say why)
- "What does \[the key term on the result] actually mean?"
- "Can I reuse this data?"

Do not pad to hit a count.

## On-page SEO

**Do:** a descriptive title with the keyword near the front; one clear H1; logical H2/H3; a
concise useful intro; a meta description promising the specific answer; internal links with
descriptive anchors; accurate structured data.

**Do not:** keyword-stuff, repeat exact-match headings, chase keyword density, invent internal
URLs, or claim any word count or density guarantees rankings.

## Scaled-content abuse — the biggest risk to this site

The hub model means adding many pages, which sits close to a line that must not be crossed.

**Do not create separate pages for:** minor keyword variations or spellings; every question in a
"people also ask" block; every city, state or ZIP unless each has genuinely different data *and*
a real reason to exist independently; every input permutation of a calculator.

A programmatic layer is legitimate **only when each page carries genuinely distinct data.** One
page per named soil series with its own official description is real. One page per "soil type in
\[city]" with the same text and a swapped name is a doorway page.

If a proposed page has no meaningful differentiation: improve an existing page, add real
functionality, or do not publish it. **More pages is not a path to better rankings.**

## Claims never to make

- Ranking, indexing, traffic, backlink or revenue promises.
- That content will appear in or be cited by AI Overviews.
- That the site or its author has expertise, credentials or experience it does not have.
- That a tool has been tested when it has not.
- That any single metric guarantees rankings.

## Never give advice

Report what the source says or what the formula works out, and cite it.

> "USDA rates this map unit *Very limited* for septic absorption fields" is a fact.
> "You can't build here" is advice, and it is the sentence that gets a site sued.

The distinction holds everywhere: state what was recorded, name who recorded it, and let the
reader decide. Where a decision needs a professional, say that a professional is needed — that
is a statement about the limits of the data, not advice about the decision.
